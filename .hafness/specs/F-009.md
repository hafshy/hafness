# F-009 — v1 loop: describe, plan, implement, feedback, on a board

Status: built

## Summary

Replace the v0 loop (plan → contract sign-off → start → handoff) with the loop the operator
approved on 2026-10-05: init, optional research, describe a spec, optionally review it,
plan it into tasks, implement, then give feedback on the result. Everything the harness
writes (specs, plans, tasks, feedback, gate runs and a log of every prompt) shows on one
generated HTML board that opens locally and publishes as an Artifact.

## Requirements

- R1 When the operator runs `/hafness-describe <idea>`, the harness shall write a spec in markdown and show it on the board.
- R2 When the operator runs `/hafness-plan F-nnn`, the harness shall write a plan and scoped tasks and show both on the board.
- R3 When the operator runs `/hafness-implement F-nnn`, the harness shall build inside each task's scope, run the logged gate, and leave the spec `built`.
- R4 When the operator runs `/hafness-feedback F-nnn <text>`, the harness shall record it and either accept the spec or turn it into new tasks.
- R5 When the operator types any prompt, the harness shall append it to `history.md`, tagged with the command name when it is a Hafness command, and the board shall show it.
- R6 When a changed file falls outside the Scope of every task in progress, the gate shall fail.

## How you'll know

- `bash test/selfhost.sh` passes: it drives the hook, the board, the lint and the fence on a fresh template.
- Opening `.hafness/board.html` in this repo shows F-009 with its plan, tasks and this run.
- `/hafness-` commands in `history.md` carry tags; plain prompts are marked `prompt`.

## Out of scope

- Rewriting `docs/01-design.md` and `docs/02-flows.md` beyond a v0 banner.
- Live reload of the local board.

## Assumptions

- `python3` is available wherever the hook runs (it parses the hook's JSON input).
- The board's markdown renderer can come from cdnjs; offline it falls back to plain text.
