Hafness · field guide

You say what you want. The gate says when it's done.

Hafness is a harness for AI coding agents, built for one person. It gives the agent a fixed way of working: write down what you asked for, plan which files it will touch, build only inside those files, and prove the result with checks it cannot switch off. Everything it writes is plain markdown, and all of it appears on one board you can open in a browser.

The loop

Seven steps, three of them optional

Each step is one command you type in Claude Code. The example follows one person building a habit-tracker iOS app from an empty Xcode project. Pick a step to see what you type, what happens, and where it stops.

    init → [research] → describe → [review] → plan → implement → [feedback] ↺· square brackets mark optional steps · feedback goes back to implement
    Who decides what

    You judge intent. The agent owns the details. The gate holds it to them.

    You decide
    • What you want built, in your own words.
    • Whether the spec's assumptions are right. Reviewing it is optional.
    • What the gate runs: you read profile.sh once, after setup.
    • Anything risky: force-pushes, migrations, new dependencies, releases, anything that sends a message.
    • Whether to give feedback once it's done. That's optional too.
    The agent handles
    • Research, when a request would otherwise rest on a guess.
    • Writing the spec, the plan and the tasks.
    • Choosing file paths, and fencing each task to them.
    • Writing the code, task by task.
    • Running the gate, and fixing what fails.
    • Keeping the resume point and the board current.
    The gate enforces
    • Every harness file keeps its format.
    • Changes stay inside the files the plan named.
    • Your project's own build, test and lint pass.
    • Three failed attempts stop the agent and hand the problem to you.
    • A task is done only with a passing run behind it.

    You are never asked to approve file paths or budgets. Those are the agent's job, and a script checks them. When a check passes, the work is done. Feedback is there for when the result isn't what you meant.

    The board

    One page that shows everything in flight

    The board is redrawn after every command and every prompt from the markdown files in .hafness/. It's a single self-contained HTML file: open it from disk, or follow the private claude.ai link the agent publishes. This preview uses the real board's layout with example data from the habit tracker, midway through its second feature. The tabs work.

    The gate

    One script decides pass or fail

    .hafness/verify.sh runs three groups of checks in order and prints one line the agent cannot reword: HAFNESS_VERIFY: PASS or FAIL. If that line is missing, the run counts as a fail.

    1 · Harness format

    The paperwork is in order

    • The map stays under 60 lines and names every file.
    • Task rows, spec status lines, feedback and run-log headers match their formats.
    • A done task cites a run that passed.
    • A done spec has no open tasks.
    2 · Scope fence

    Nothing changed outside the plan

    • Every changed file must sit inside the Scope of a task in progress.
    • The gate's own files (verify.sh, profile.sh, policy.md) count too, unless a task names them.
    3 · Your project

    It builds, and the tests pass

    • Build, test, lint and typecheck, exactly as written in profile.sh.
    • Any extra checks you added there.
    • A profile with nothing runnable refuses to pass.
    PASS

    Done

    Each task in progress becomes done and carries the run id. The spec becomes done. The agent stops with a card telling you how to try it.

    FAIL

    Fix and retry

    The agent fixes the failing check and runs the gate again. It never widens the scope or edits the gate to get a pass. The gate counts the attempts itself.

    ESCALATED

    Your call

    The third failure stops the agent. It writes what it tried and what the evidence said, then waits for you.

      Picking up later
      
      
      A new session never has to ask where you were
      
      
      Open a new terminal with no chat history. The agent reads state/current.md, checks whether the last session stopped halfway through a task, and prints four lines before it touches any code. You don't have to explain anything again, and that's the test of the whole harness.

      Commands
      
    
      Install once, then seven commands
      
  
      
  
      npx skills add hafshy/hafness -a claude-code -y
      
  
      
    
      /hafness-initOnce per project. Sets up .hafness/, finds your build and test commands, draws the first board.
      
    
      /hafness-research <topic>Optional. A sourced one-page note before you commit to anything.
      
    
      /hafness-describe <what you want>Your idea becomes a spec: what it does and why, never which files.
      
    
      reviewedOptional. Say it after reading a spec to mark it reviewed.
      
    
      /hafness-plan F-001The spec becomes a plan and a list of tasks, each fenced to its files.
      
    
      /hafness-implement F-001Builds task by task and runs the gate. A pass makes the spec done.
      
    
      /hafness-feedback F-001 <what you saw>Optional. Turns what you saw into new tasks and reopens the spec.
