# Contract F-001 — Plugin scaffold

Status: signed off · 2026-09-15

## Goal

The Hafness repo loads as a Claude Code plugin *and* installs with one `npx skills add`
command, exposes five skills as stubs, and ships `template/` inside the init skill so
`/hafness-init` has something to copy. No skill does real work yet.

## In scope

- `.claude-plugin/plugin.json` — `name`, `version`, `description`; nothing else
- `skills/hafness/SKILL.md` — routing only, points at `.hafness/HAFNESS.md`
- `skills/hafness-{init,start,plan,contract,handoff}/SKILL.md` — stubs
- `git mv template skills/hafness-init/template` — shipped as `.hafness/`, dot kept
- `README.md`, `HANDOFF.md`, `docs/04-files.md` — path and install-command updates only
- `.hafness/profile.sh` — `HAF_LINT` gains a manifest + skills presence check

## Out of scope

Named explicitly, because this is the half that prevents drift.

- Any skill logic. Stubs print their intent and exit.
- Stack detection of any kind — that is F-002
- `journal` and `audit` skills — v1
- Hooks, `agents/`, `.mcp.json`, `marketplace.json` — phase three or never
- Changing anything under `docs/` beyond the paths named above

## Done criteria

- [ ] `claude --plugin-dir .` loads without error and lists six `hafness*` skills
- [ ] `npx skills add ./ -a claude-code -y` into a scratch dir yields six skill folders,
      `hafness-init/template/.hafness/` intact (the dot survives the installer)
- [ ] `skills/hafness/SKILL.md` routes to `.hafness/HAFNESS.md` and nothing else
- [ ] All five `/hafness-*` skills are invocable and print what they will do
- [ ] `bash .hafness/verify.sh` exits 0 in this repo

## Acceptance evidence

A run block in `log/` whose verdict line is `HAFNESS_VERIFY: PASS`, plus the output of
invoking each of the five skills once and the `ls -R` of the npx-installed scratch dir.

## Settled before writing (was the open question)

Checked against current Claude Code docs and the `skills` CLI README on 2026-09-15:

- Manifest is `.claude-plugin/plugin.json`; only `name` is required.
- `commands/` is legacy; docs say "use `skills/` for new plugins". Each command is
  `skills/<name>/SKILL.md`, invocable as a slash command.
- `npx skills add` scans `skills/*/SKILL.md` and copies each skill directory. Anything a
  skill needs must live inside its own directory — hence `template/` moves.
- A skill named `init` installs as bare `/init` via npx and collides with the built-in.
  Hence `hafness-<verb>`. Plugin path spells it `/hafness:hafness-init`; accepted.
